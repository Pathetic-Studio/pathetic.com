PATHETIC WEBSITE — TYPOGRAPHY AUDIT
===================================
Audit date: 2026-09-01
Scope: customer-facing website, case-study/careers/privacy routes, navigation,
modals, footer, and Meme Booth UI. Sanity Studio and temporary debug/test pages
are excluded because they are authoring/development tools rather than site UI.


1. FOUNDATIONS
--------------

Typeface
  Arial Narrow (local WOFF2), normal/italic at 400 and 700.
  Source: app/layout.tsx
  Global Tailwind family: font-sans / --font-sans.

Root sizing
  Browser root is 16px. Rem conversions below therefore use 1rem = 16px.

Responsive bands used by the current site
  Mobile: 0–639px
  Tablet: 640–1023px
  Desktop: 1024px+
  Note: TitleText's transform presets call 0–767px mobile and 768–1023px
  tablet; some legacy components also switch at md/768px or xl/1280px.

Canonical semantic scale (components/ui/text-styles.ts)
  micro          10px mobile / 12px tablet+
  label/caption  12px mobile / 14px tablet+
  nav/link       14px mobile / 16px tablet+ (nav remains 14px)
  body compact   14px mobile / 16px tablet+
  body           16px mobile / 18px tablet+
  body large     18px mobile / 20px tablet+
  section body   18px mobile / 20px tablet+
  card title     20px mobile / 24px tablet+
  subheading     24px mobile / 32px tablet+
  data title     16px mobile / 18px tablet / 20px desktop
  data value     14px mobile / 16px tablet / 18px desktop

  These roles are exported as TEXT_STYLES. Shared maximum line lengths are
  exported as TEXT_WIDTHS. Art-directed display headings remain TitleText
  presets because their transformed geometry is part of the scene design.

Shared section-header body role
  Mobile: 18px / line-height 1.08 / weight 500 / tracking -0.025em
  Tablet: 20px / line-height 1.08 / weight 500 / tracking -0.025em
  Desktop: 20px / line-height 1.08 / weight 500 / tracking -0.025em
  Width: min(86vw, 36rem) mobile; min(84vw, 36rem) tablet+;
         hard maximum 36rem / 576px.
  Token: SECTION_HEADER_BODY_CLASS
  Source: components/ui/text-styles.ts
  Current users: What We Do, Matrix, Network intro, And We Bring Friends.

3. STROKE COMPARISON
--------------------

TitleText supports centre strokes and outside strokes. For outside strokes it
renders twice the supplied outlineWidth behind the fill, so the visible outward
thickness remains approximately the requested value without eating the glyph.

Use                                      Input      Rendered CSS stroke   Position
Page loader / intro title                1.5px      3px                   outside
Lifecycle slide centre titles            1.5px      3px                   outside
Credibility title                        CMS        CMS x2 if outside      CMS-selectable
Network “And We Bring Friends”            2px        4px                   outside
What We Believe                           3px        6px                   outside
Work With Us                              2.5px      5px                   outside
Case-study hero                           2px        4px                   outside
Newsletter modal heading                 2px        2px                   centre/default
Network editable brand label              2px        2px                   direct CSS
Basket labels                             2–3px      2–3px                 direct CSS
Basket Shop heading                       2–4px      2–4px                 direct CSS
Basket newsletter heading                 1.5–3px    1.5–3px               direct CSS
Legacy bendy-arm/meme copy                2px        2px                   direct CSS

Implemented rule
  Display strokes now scale with the display hierarchy rather than applying one
  visually thinner value to every heading:
    standard / intro-sized: 1.5px outside (3px CSS paint)
    large:                  2px outside (4px CSS paint)
    monumental:            2.5px outside (5px CSS paint)
  Intro and lifecycle titles use standard. And We Bring Friends and case-study
  hero titles use large. What We Believe and Work With Us use monumental.
  Credibility keeps its CMS-selectable stroke because its current authored
  result is the second approved reference. Small decorative labels keep their
  direct 2–3px white keyline.

7. MEME BOOTH UI
----------------

The booth intentionally uses a compact product-UI hierarchy rather than the
marketing display hierarchy:
  Micro/status/fine print: 10px.
  Labels, errors, credit controls: 12px.
  Fields, toggles, actions: 14px.
  Camera actions: 16px semibold italic uppercase.
  Modal headings: 20px bold uppercase.
  Prices: 18px bold.
No text strokes are used in the booth controls.


8. CURRENT CONSISTENCY FINDINGS
-------------------------------

Resolved in this pass
  • What We Do, Matrix, Network intro, and And We Bring Friends now share one
    section-header body type role and the same 36rem max width.
  • And We Bring Friends no longer uses its smaller .94/1.15rem one-off body.
  • Shared page headers, hero support copy, section headers, CTA copy, grid
    cards, animated grid cards, grid text blocks, and image-card links now use
    TEXT_STYLES/TEXT_WIDTHS instead of defining parallel local ladders.
  • Network reach labels and detail stars now use the shared label/data roles.
  • Primary display outlines use DISPLAY_OUTLINE_WIDTH (1.5px outside) unless
    a CMS-authored or deliberately decorative treatment overrides it.

Still deliberately bespoke
  • Lifecycle scene titles and meme typography.
  • Basket object labels and retro popup typography.
  • Bingo footer grid labels.
  • Meme Booth compact application UI.

Remaining hierarchy debt found by the audit
  • PortableText h1–h5 have no intrinsic hierarchy and inherit body size.
  • Legacy Hero 1 uses direct 36/48/60px headings instead of TitleText.
  • The old footer and Bingo footer intentionally use different link scales.
  • Several object-detection and work-card labels are direct local styles.

Rules for future additions
  1. Use TitleText only for display/art-directed headings.
  2. Use TEXT_STYLES for all supporting copy, labels and links.
  3. Use TEXT_WIDTHS for readable line length; do not create a new viewport
     width inside an individual section unless the layout genuinely requires it.
  4. Use DISPLAY_OUTLINE_WIDTH with outside paint for primary display titles.
  5. Preserve bespoke scene/decorative exceptions and document new ones here.
  6. If rich-text heading hierarchy becomes editor-facing, add explicit
     PortableText heading roles rather than allowing body-size inheritance.
